## Xiora AI Prompt: 導入後 30 日 ヘルスチェック

Phase 0 実装後 30 日で実施する Health Check を以下 5 軸で構造化してください。

軸:
1. **actual vs planned** — 想定していた時間節減 / 金額節減 と 実測値 の差 (%)
2. **failure modes** — 実運用で発生したエラー・停止・想定外挙動 (件数と対応履歴)
3. **kill switch invocations** — Kill Switch が発動したケース (発動理由と正当性判定)
4. **user adoption** — 現場担当者が実際に使えているか (実 log での確認)
5. **next Phase readiness** — Phase 1 に進む条件 (Phase 0 が 3 週間 安定稼働 + user 満足度 4/5 以上) を満たしているか

出力構造:
```
[会社名] × Xiora Systems Phase 0 Health Check (実施日: YYYY-MM-DD)

■ Executive Summary (3 行以内)
■ 軸別 詳細
  - 1. actual vs planned:
    - 節減時間 実測: X 時間/月 (計画 Y 時間/月、達成率 Z%)
    - 節減金額 実測: ¥XXX,XXX/月 (計画 ¥YYY,YYY/月、達成率 Z%)
  - 2. failure modes:
    - Error #1: ...
  - 3. kill switch: ...
  - 4. adoption: ...
  - 5. next phase readiness: ...

■ Phase 1 実施判定
- [ ] 実施推奨
- [ ] 継続監視 (2 週間 追加観測)
- [ ] Phase 0 の設計修正 が先

■ Reo からの Note (定性)
- 短く 3-5 行
```

制約:
- 数字は 顧客側から提供される actual log 実測値のみ、推測しない
- Phase 1 判定は 3 択のみ、曖昧な結論を避ける
- adoption の判定は「使ってる」ではなく「業務が変わった」で評価
