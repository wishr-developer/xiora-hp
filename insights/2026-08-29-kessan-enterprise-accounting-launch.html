Kessan (決算) LIVE — 中堅企業・自治体 向け 会計 · 決算 統合 プラットフォーム 開放

公開: 2026-08-29 · Xiora Engineering · Real SaaS #11 · Enterprise Grade

Xiora が 中堅企業 · 自治体 向け に 会計 · 決算 統合 プラットフォーム 「Kessan (決算)」 を LIVE 化 しました。 複式簿記 + 決算 (B/S · P/L) + 電子帳簿保存法 対応 + インボイス制度 対応 + hash chain 監査ログ + RBAC の 11 モジュール 統合。 Free tier で 30 仕訳 まで 全 機能 が 試せます。

なぜ 作ったか

日本 の 会計 SaaS 市場 は 2 極 化 して います:

  • 個人事業主 · 小規模 事業者 向け: freee / MoneyForward / 弥生 が 月額 ¥1,000-¥5,000 で 提供。 UI は 使いやすい が 中堅 規模 の 統合 会計 · 監査 対応 に は 機能 が 不足。
  • 大企業 · 上場 企業 向け: SAP · 勘定奉行 · 弥生販売 プロフェッショナル 等 が 月額 ¥50,000+ で 提供。 導入 に 数ヶ月 · 数百万 円 の コスト。

その 間 の 「中堅企業 (30-300 人) · 自治体 財務課 · 会計事務所」 に とって、 電子帳簿保存法 · インボイス制度 対応 の 統合 会計 SaaS が 空白 地帯 でした。 Kessan は この 空白 を 埋める 「国 レベル」 品質 の 会計 プラットフォーム です。

11 モジュール 統合

記帳 (M-001 〜 M-003)

M-001

勘定科目 マスタ

日本 中小企業 会計 指針 準拠 の 60+ 標準 科目 (資産/負債/純資産/収益/費用) を 事前 seed。 自社 追加 科目 も 対応。 subtype で B/S · P/L 自動 集計。

M-002

仕訳 起票 (複式簿記)

借方/貸方 バランス チェック (mismatch 時 IMBALANCE エラー)、 記帳 後 削除 不可 (電子帳簿保存法 遵守)、 訂正 は 反対仕訳 で。

M-003

総勘定 元帳

科目 別 期間 別 の 取引 一覧、 running balance 計算、 相手 科目 表示、 摘要 · 参照 番号 保持。

決算 (M-004 〜 M-006)

M-004

試算表

全 科目 の 借方/貸方 発生 と 残高 集計。 一定 時点 の 財政 概要 が 一目 で。 貸借 一致 検証。

M-005

損益計算書 (P/L)

売上高 · 売上原価 · 販管費 · 営業外 · 特別 · 法人税 で 自動 集計。 段階 利益 (売総/営業/経常/税引前/当期) を 表示。

M-006

貸借対照表 (B/S)

資産・負債・純資産 を section 別 に 集計。 当期純利益 は P/L と 自動 連動。 貸借 一致 (資産 = 負債 + 純資産) を 常時 検証。

ガバナンス · コンプライアンス (M-007 〜 M-011)

M-007

監査ログ (hash chain)

全 操作 に SHA-256 の 前後 リンク hash、 改ざん 検知 API (/api/audit/verify) で 全 log の integrity を 検証。 監査法人 対応。

M-008

RBAC (4 role)

owner (全 操作) / accountant (起票 · 閲覧) / viewer (閲覧 のみ) / auditor (監査ログ 読取 のみ) の 4 role を 分離。

M-009

インボイス 登録番号 検証

T + 13 桁 の check digit (mod 9) を 検証 する API + 適格 事業者 マスタ で 保存 · 自動 参照。

M-010

マルチ 組織 · 会計期間

1 user が 複数 組織 (子会社 · 部門) を 切り替え。 会計 期首 月 は 組織 単位 で 設定。

M-011

CSV エクスポート

電子帳簿保存法 対応 の 標準 CSV export。 既存 会計 ソフト (freee/MoneyForward/弥生) 移行 も 可能。 vendor lock-in なし。

電子帳簿保存法 · インボイス制度 対応 の 実装

1. 記帳 後 削除 不可 (電子帳簿保存法)

Kessan は 記帳 (POST /api/journals) 後 の 仕訳 レコード に DELETE エンドポイント を 提供 しません。 訂正 が 必要 な 場合 は 反対仕訳 (reversal) を 追加 起票 し、 元 データ は そのまま 保持。 これ で 「訂正 · 削除 の 履歴」 の 保存 要件 (電子帳簿保存法 第 8 条) を 満たします。

2. Hash chain 監査ログ (改ざん 検知)

各 操作 (org.create / member.invite / coa.create / journal.post / journal.reverse / vendor.create / org.upgrade / org.plan_change) は 監査ログ に 記録 されます。 各 entry は 前 entry の hash を 含めて SHA-256 で hash 化。 途中 で 1 件 でも 改ざん されれば chain が 破綻 し 検知 可能。

GET /api/audit/verify { "total_entries": 4, "chain_head": "5aca51823a4c0eac...", "integrity_ok": true, "breaks": [] }

3. インボイス 登録番号 check digit 検証

適格 請求書 発行 事業者 の 登録番号 (T + 13 桁 数字) は、 12 桁目 まで の 加重 sum を mod 9 で check digit と 照合 する 標準 検証 を 実装。 vendor マスタ 登録 時 に 自動 検証。

GET /api/masters/validate-invoice-registration?number=T1234567890123 { "valid": false, "reason": "checksum 不一致 (expected 7, got 3)" }

技術 構成

  • Backend: Cloudflare Pages Functions (serverless、 auto-scale)
  • Data: Cloudflare KV × 5 namespace (users / orgs / data / audit / sessions) — 自社 保管、 第三者 データ 送信 なし
  • Auth: magic-link (パスワード レス) + HttpOnly Secure Cookie + org-scoped role
  • Frontend: バニラ HTML/JS SPA (依存 ゼロ、 サポート 容易)
  • Billing: Stripe LIVE (org-level subscription、 owner のみ アップグレード 可能)

実 動作 例 (E2E テスト 済)

「テスト 株式会社」 という 組織 を 作成 し、 3 つ の 仕訳 を 起票:

  1. 資本金 3,000,000 円 出資 (普通預金 借方 · 資本金 貸方)
  2. A社 SaaS 導入 支援 500,000 円 掛売 (売掛金 借方 · 売上高 貸方)
  3. クラウド インフラ 費用 80,000 円 支払 (通信費 · 消耗品費 借方 · 普通預金 貸方)

結果:

  • 試算表: 借方 ¥3,500,000 = 貸方 ¥3,500,000 ✅ 貸借 一致
  • P/L: 売上高 ¥500,000 − 販管費 ¥80,000 = 当期純利益 ¥420,000
  • B/S: 資産 ¥3,420,000 = 純資産 ¥3,420,000 (資本金 ¥3,000,000 + 当期純利益 ¥420,000) ✅ 貸借 一致
  • 監査ログ: 4 entry (org.create + journal.post × 3), integrity_ok = true
