Xiora Ocean — 日本 SMB × solo founder × AI エージェント のための独自 LLM 構想

汎用 LLM ではなく、日本の中小企業 / 個人起業家 / AI エージェント運用 に特化した「日本製 LLM Ocean」を Xiora が自社開発する構想。 P0 skeleton から P5 商業提供までの roadmap と、なぜ我々がこの領域に賭けるかを整理します。

KR
沓澤 怜士 (Kutsuzawa Reo)
Xiora 代表 · info@xiora-official.com

なぜ 汎用 LLM だけでは足りないのか

Claude / GPT-4o / Gemini のような汎用 LLM は驚異的な性能を持っています。 Xiora の日常運用でも、Ollama で回している qwen2.5:7b や Claude API を「借用」する形で、AI エージェント 12 名が 24/7 動いています。

ただし、我々が長期的に構築したい「日本 SMB × solo founder × AI エージェント」というドメインには、汎用モデルでは埋まらない gap があります。

  • 日本語 SMB 特有の商習慣・会計・法令の常識が薄い — 補助金申請書式、青色申告、消費税インボイス制度、電子帳簿保存法 等の実務詳細。
  • ソロ運用の意思決定 pattern に対応する内部表現が浅い — 「Time-to-first-yen 昇順」「Absolute gate 5 種類」「Zero-spend policy」のような solo founder 特有の判断軸。
  • AI エージェント自体の運用ログ・失敗パターンで学習していない — 汎用モデルは AI 運用の meta-cognition が浅い。

汎用 LLM は「広く浅く」で商業提供されています。 我々の課題は「日本 SMB × solo × AI エージェント」の 3 交点で「狭く深く」を作ることです。

Ocean プロジェクトの位置付け

Ocean は Xiora が自社開発する内部 codename の独自 LLM プロジェクトです。 事業ブランド Xiora の傘下に置き、外部からは「Xiora Ocean」として認知されるよう命名分離しています。

  • Ocean = 内部技術 codename、Xiora 傘下の独自 LLM プロジェクト
  • Xiora = 事業ブランド、対外表記の統一名
  • Nexa / Gourmie / Kigen 等 = Xiora が提供する product line、Ocean を含む複数 AI stack の上で動く

この命名分離により、tech スタックの内部進化 (Ocean P0 → P5) と、ブランド安定性 (Xiora) を両立させています。

Ocean が担う独占ドメインの 3 要素

汎用 LLM に対抗するのではなく、汎用 LLM が「行けない」ドメインに深く入る戦略です。 我々が独占を狙う 3 要素は以下です。

1. 日本 SMB 商習慣・会計・法令の内在化

青色申告、電子帳簿保存法、インボイス、補助金申請フォーマット、Stripe/税務署対応の実務ドキュメントを学習素材に組込みます。 汎用 LLM は「知っている」レベルですが、Ocean は「使える」レベルを目指します。

2. Solo founder / AI エージェント運用の意思決定 pattern

Xiora の日常運用ログ (Reo との会話、AI 12 社員の判断履歴、Absolute gate 発動履歴、Time-to-first-yen 順の判断軌跡) を moat として学習に組込みます。 これは公開データセットでは手に入らない性質の unique data です。

3. AI エージェント運用の meta-cognition

「AI エージェントが AI エージェントを運用する」ときに必要な視点 (halt 判定、egress-check、憲法 5 条準拠、時間軸判断) を Ocean 内部に埋め込みます。 汎用 LLM は「言語生成」に最適化されていますが、Ocean は「AI 運用の判断」に最適化します。

P0-P5 Roadmap

実現には数年単位のスパンが必要です。 現時点 (2026-07 末) の位置と、その先の想定 phase を以下に示します。

P0 — Skeleton (2026-07 完了)

  • 設計 spec の確定 (architecture / data moat / roadmap)
  • 推論は Ollama (qwen2.5:7b) を借用、実 training は未実行
  • zero-spend で走る (Mac local + Ollama、追加課金なし)

P1 — Data corpus 構築 (2026-Q3-Q4)

  • Xiora 4 unique data source を pipeline 化 (agent log / Rei-Reo 会話 / memory / Universal KG)
  • 外部 upload 禁止 (moat 保護)
  • 公開 OER (Open Educational Resources) と 商用可 licence 素材のみ追加

P2 — Fine-tune 開始 (2027-Q1)

  • Base model 選定 (Llama / Qwen / Gemma 系 の商用可 model)
  • GPU rental 開始 (¥15-40 万/月 想定、Xiora billing Absolute gate)
  • Ocean v0.1 (fine-tuned checkpoint) release

P3 — 内製推論 stack 稼働 (2027-Q2)

  • 推論を Ocean 自身で担当 (Ollama 借用から自立)
  • Xiora 内部の全 AI エージェントの一部 workload を Ocean に切替
  • Fallback として Claude / GPT-4o を 並列稼働 (routing 判断)

P4 — 外部 API 商業提供 (2027-Q3-Q4)

  • api.ocean.xiora-official.com 経由で API 提供
  • 日本 SMB / solo founder 向けの pricing (¥1,980-¥9,800/月 想定)
  • Xiora 既存 product (Nexa / Gourmie / Kigen) が Ocean を活用

P5 — Ocean エコシステム化 (2028+)

  • 第三者開発者向け fine-tune API / adapter
  • 日本 SMB 向け vertical LLM の代表格として認知獲得
  • 研究論文 / 学会発表 で認知構築

Zero-spend policy との整合

P0-P1 は zero-spend で走ります。 追加課金は P2 の GPU rental (¥15-40 万/月) から発生するため、それまでに Xiora 全体で MRR ¥50 万 以上を達成することが前提です。

これは技術的な roadmap であると同時に、Xiora 事業全体の revenue milestone と紐付いた投資計画でもあります。 「AI 会社を装う」ためではなく、「収益に裏付けられた AI 投資」として設計しています。

他社の日本製 LLM との差別化

日本国内でも rinna、LINE-Qwen、ELYZA-Japanese、Preferred Networks 等の日本製 LLM が公開されています。 これらは「日本語一般性能」の高さで prominent です。

Ocean が同じ土俵で競う予定はありません。 我々の差別化軸は以下です。

  • 汎用日本語性能ではなく、日本 SMB × solo × AI エージェント運用ドメイン特化
  • 公開データセットではなく、Xiora 自社運用ログという unique moat
  • 研究モデル公開ではなく、Xiora の product に組込まれた商業提供

「小さくても唯一」を狙うポジショニングです。 汎用大型 LLM の対極にある「vertical で深い」LLM の代表格を目指します。

Reo が今できる関与

Ocean は現在 P0 (設計・skeleton 段階)です。 貴社が興味を持たれる場合、以下の関わり方があります。

  • 日本 SMB 業界の実務データ提供 (パートナー枠) — 業界特化コーパスへの寄与
  • P4 API 商業提供時の early access 予約 — 2027 Q3 launch 予定の初期ユーザー枠
  • Xiora の他 product (Nexa / Gourmie / Kigen) を先に導入 — Ocean の恩恵は自動的に反映される設計

Ocean 単独ではなく、Xiora 全体の product stack を通じて提供する構造です。

この構想は Xiora の資本規模で実現可能か

Xiora は現時点 solo 運用の小さな会社です。 数億円規模の research budget を投じる大企業型 LLM 構想とは対極にあります。

我々の approach は以下 3 点で「小規模で実現可能」に設計しています。

  • 汎用性能で戦わない — vertical 特化で計算量・データ量を絞る
  • base model 選定 + fine-tune の path (ゼロから pretrain しない)
  • P2 で初めて GPU 課金、そこまでは zero-spend で骨組み構築

これでも数千万円規模の投資は最終的に必要です。 それを賄うのが Xiora の既存 product 群 (Nexa / Gourmie / Kigen / Aiverse Studio 等) の revenue です。 Ocean は「Xiora 事業が育つほど深く育つ」flywheel 構造で設計しています。

まとめ

Ocean は Xiora の 5 年計画の中で最も長期の投資対象です。 今すぐの revenue には直結しませんが、日本 SMB × solo founder × AI エージェント運用 という交点で「後発の巨人」に模倣されにくいドメインを取りに行く構想です。

汎用 LLM 各社が「広く強く」を追う中で、我々は「狭く深く、そして日本の実務に埋め込む」に賭けます。 P4 商業提供 (2027-Q3-Q4) に向けて、data corpus と fine-tune 環境を粛々と準備していきます。
