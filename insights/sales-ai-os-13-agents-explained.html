なぜ 13 の agent に分けたか

営業は 「Lead → Research → Scoring → Content → Review → Outreach → Conversation → Appointment → Proposal → Contract → Billing → CRM → Analytics」の 13 工程に分解できます。 1 つの巨大 agent に全部やらせる vs 分業させる vs 半自動化 の 3 択の中で、Sales AI OS は分業を選びました。 各 agent が独立してテスト可能で、失敗時の局所化ができるからです。

Lead agent — 公開情報からリード収集

Google Maps · 商工会議所 名簿 · 業界 DB · SNS の 4 経路 から robots.txt 遵守で lead を収集。 各 lead に industry / employee_count / recent_news の 3 属性を最低限持たせます。 個情法 の 「公開情報の適正取得」に該当する範囲のみを収集、非公開データは 一切扱いません。

Research agent — 会社分析 3 軸

DX 度 (公式サイト の技術 stack から推定) · SEO 順位 (10 主要 KW での順位) · 採用状況 (公開求人 URL の 有無) の 3 軸で 会社を分析。 各分析には根拠 URL を必ず記録、Scoring 時に参照。

Scoring agent — 100 点満点 + 根拠

Research 結果 + Lead 属性 を 特徴量 として、100 点 scoring。 60 点未満 = 送信対象外、60-79 = follow up 対象、80+ = 即座に Content agent に引き渡し。 判定根拠を 5 行以内で必ず出力、ブラックボックス scoring 禁止。

Content agent — テンプレ感のない文面

件名 20 字 + 本文 300-500 字 の 個別 pitch を生成。 SPECIFIC_FACT slot (会社固有の事実、Research から引用) を必ず埋め込み、テンプレ blast を回避。 A/B test は subject 5 パターン × 本文 3 パターン = 15 バリアント。

Review + Outreach agent — 送信 gate + 予約

Review agent は 生成文面 を 憲法 (押し売り禁止 / 誇大表現禁止 / 景表法 / 特商法) の 4 pass で 検査。 pass すると Outreach agent が送信予約 (24 時間 内 同一 domain 1 通 制限、SMTP は Postfix relay 経由)。

契約 / 決済 は 必ず 人の gate

Contract + Billing 2 agent は自動化不可 の Absolute gate 領域。 電子契約 の 承認、 大口決済 の 承認、返金 は 必ず人 (owner ロール のみ) の承認 gate を通過します。 これで 完全自動化 が 「暴走」に至らない設計。

Salesforce との比較

Salesforce Sales Cloud は 汎用 CRM、Sales AI OS は 完全自動営業。 対比表: 人 の工数 (SF: 常時 vs SaOS: 承認のみ) / 初期学習 (SF: 数週間 vs SaOS: sign up で 即 稼働) / 単価 (SF: $25-300/user/月 vs SaOS: ¥3,000-¥100,000/組織/月)。
