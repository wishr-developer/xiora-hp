差別化 factor 1: 20 体 設計 中 の AI agent (現在 17 α 稼働) が 分業 する 無人 EC 運営

EC-Autopilot は 商品 選定 / 仕入 先 検索 / 価格 追跡 / 商品 説明 生成 / SEO 最適化 / 発送 手配 / CS 応答 / return 処理 等、EC 運営 の 20 工程 を それぞれ 別 の AI agent が 分業 する 前提 で 設計 されて います。

  • 商品 選定 agent · 売れ筋 tracking + margin 計算 で 候補 提示
  • 仕入 agent · 複数 仕入 先 の 価格 比較 + 在庫 確認
  • 商品 ページ agent · 説明 文 / SEO tag / 画像 optimize を 一括 生成
  • CS agent · 問い合わせ を intent 分類 + draft 生成
  • return agent · 返品 依頼 の 判定 + 返金 処理 flow 自動 化

Shopify / BASE / STORES は EC platform と して の 基盤 は 提供 する もの の、上記 20 工程 は 事業者 が 手動 or 別 app 導入 で 対応 する 前提。

差別化 factor 2: 承認 flow L0-L5 (人間 gate 制御)

「AI が 勝手 に 商品 出品 / 発注 / 返金 する」の は 事業 者 と して 責任 の 所在 が 曖昧 に なる 課題 が あります。 EC-Autopilot は 全 AI action に 6 段 の 承認 flow (L0 = 完全 自動, L1-L4 = 段階 承認, L5 = 人間 のみ) を 用意 して います。

  • L0 (完全 自動) · 単価 ¥1,000 未満 の 商品 追加 / 説明 文 更新 等
  • L1-L2 (email 通知 → 24h 後 自動) · 単価 ¥1,000-10,000 の 出品 / 変更
  • L3-L4 (Slack 通知 + 明示 承認 必須) · 単価 ¥10,000+ の 出品 / 返金 判定
  • L5 (人間 のみ) · 契約 締結 / 銀行 口座 変更 / 大口 返金 (¥100,000+)

差別化 factor 3: Stripe 決済 + SAQ-A 準拠 (PCI DSS の 最軽量 分類)

EC 事業 者 が 直接 カード 番号 を 扱う と PCI DSS の 全 400+ 項目 監査 が 必要 に なり、実務 上 SMB では ほぼ 不可能。 EC-Autopilot は Stripe Checkout / Stripe Elements 経由 の 決済 のみ 対応、カード 番号 は 事業者 サーバー を 通ら ない SAQ-A 準拠 (最軽量 分類、監査 20 項目 前後) の 前提 で 設計 されて います。

差別化 factor 4: 日本語 native UI + 国内 適格 請求書

Shopify は 日本語 UI 対応 進んで います が、深部 の 設定 / 契約 書 / support は 英語 が 中心 の 想定。 EC-Autopilot は 開発 元 が 日本 (Xiora Systems)、UI + support + 契約 書 + 請求 書 全て 日本語 で 完結 + 国内 適格 請求書 (invoice) 自動 発行。

どんな 事業 者 に EC-Autopilot が fit する か

  • 無在庫 EC / ドロップシッピング: 商品 選定 と 出品 が bottleneck に なりやすい → 20 agent で 自動 化
  • 副業 EC (本業 別): 承認 flow で「重要 決定 のみ 通知」設定 可、時間 節約
  • SMB 経営 者 が 1 人 で 運営: CS / return / 商品 更新 を AI 任せ、経営 判断 に 集中
  • Shopify / BASE 手数料 で 利益 圧迫: 月額 定額 で コスト 上限 を 確定

どんな 場合 Shopify / BASE / STORES が 合う か

  • 自社 商品 (アパレル / 食品 / ハンドメイド) を 販売、在庫 管理 が 主業務
  • 越境 EC (US/EU / 中華圏 出品)、Shopify Payments で 多 通貨 対応 が 必要
  • 店舗 併営 (POS 連携 が 必要)
  • 既 に Shopify + apps で 稼働 中、移行 コスト より 継続 コスト が 低い
