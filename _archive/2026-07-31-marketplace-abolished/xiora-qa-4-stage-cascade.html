What's inside

含まれる もの

  • Stage 1 (Build) prompt template — 実装 完了 直後 の self-report 形式 (期待 表示 · 変更 file 一覧 · rollback 手順 3 点)
  • Stage 2 (Fact check subagent) prompt — 具体 claim 抽出 + 該当 file/line 確認 + 数値 · 日付 · price · URL の 実物 verify 手順
  • Stage 3 (Multi-view subagent) prompt — UX / brand / conversion / SEO / mobile / a11y の 6 視点 rubric (視点 選択 は build 種別 で 分岐)
  • Stage 4 (Browser MCP verify) prompt — claude-in-chrome MCP で 実 URL を 開き screenshot + console + network の 3 面 verify
  • Orchestration script (bash + Python) — 4 段 を 順に 実行 · fail 時 の 巻き戻し · Stage 1+4 の 小 fix 圧縮 mode
  • 判定 rubric (JSON) — 全 段 の pass / fail 条件 · 15 チェック 項目 · false positive 事例 集
  • Claude Code / Cursor / Aider 向け の 使い分け ガイド (1 pack 内 に 3 パターン)
  • README.md 5,000 字 (何 を もって pass と 呼ぶか · 事故 patterns · 圧縮 判断)

Where to use

使い どころ

  • Claude Code / Cursor / Aider で LP · landing page · SaaS 機能 の build を 走らせる 単独 founder
  • 「AI が build → 自分 が 目視」 の workflow で 見落とし が 頻発 する team
  • fact-only tone / 誇大 表現 排除 を 全 build に 徹底 したい 場合 (景表法 対策)
  • UX / brand / conversion / SEO / mobile / a11y の 6 視点 を 毎回 別々 に 走らせる のを 1 pack で まとめたい 場合
  • browser MCP (claude-in-chrome) 前提 の 客観 verify を 標準 化 したい 場合
